## 2026-11-16 模型目录接入 Codex

### 背景

用户希望把本网关支持的 13 个模型加进 Codex 的模型目录
`C:/Users/xzs/.codex/bridge_models.json`，使 Codex 可以直接选用。

### 需求项

| 编号 | 需求 | 状态 | 落地位置 |
|---|---|---|---|
| R8 | 从 `http://127.0.0.1:8790/` 获取支持的模型 | 完成 | `GET /v1/models`，13 个 |
| R9 | 追加到 `bridge_models.json`，不破坏原有 77 条 | 完成 | 77 → 90 条，原有零改动 |
| R10 | 网关应能识别带命名空间前缀的模型名 | 完成 | `catalog.StripModelPrefix` |
| R11 | 让 Codex 真正能路由到这 13 个模型 | 完成 | `config.toml` 的 `[model_providers.qoder]` + `qoder.config.toml` |
| R12 | 导入脚本可重复运行且不重复写入 | 完成 | `tools/add_qoder_models.py`（幂等） |

### 关键约束（实测得出，非推测）

1. **Codex 不按 slug 前缀选 provider**。slug 原样作为 `model` 字段发给当前
   `model_provider` 的 `base_url`。所以 `qoder:` 前缀只是给网关看的命名空间，
   请求必须走 `qoder` provider。
2. **网关对解析不了的模型名静默按 `auto` 透传**（返回 200、`credits=0`），
   不报错。这意味着「名字写错」和「名字写对」在客户端看来都是成功。
3. **站点的 `ss` provider 不服务 Qoder 模型**：实测 `qoder:Qwen3.8-Flash` 与裸名
   `Qwen3.8-Flash` 都返回 `503 model_not_found`。

### 验收标准

- `codex debug models` 能完整解析 90 条，无报错。
- `codex --profile qoder exec "..."` 输出正确，且网关侧 `credits` 非 0。
- 13 个模型逐个实测：HTTP 200 且 `credits` 非 0（证明未退化成 auto）。
- 默认配置（`model_provider = "ss"`）保持不变，切换是显式加 `--profile qoder`。
