# 踩坑笔记

按「发现顺序」记录，每条都带定位手段与修复结论。编号前缀：
`G` = Go 移植期，`Q` = Qoder 协议/网关，`C` = Codex 接入，`R` = 仓库卫生。

---

## G1 · Go 的 regexp 是 RE2，不支持前瞻断言

Python 版有几处 `(?=...)`（`_CALL_TAG_LEAD_RE` 等）。直接照搬会导致
**启动即 panic**：

```
panic: regexp: Compile(`^\s*([A-Za-z_][A-Za-z0-9_.:\-]*)\s*(?=[,:=]|[({\[]|$)`):
error parsing regexp: invalid or unsupported Perl syntax: `(?=`
```

**修法**：把前瞻改写成「捕获分隔符，再由调用方裁剪」。没有别的选择——RE2 不回溯，
这是设计约束而非 bug。

**定位手段**：`go test ./internal/guards/` 会在 init 阶段就 panic，堆栈直接指向
`regexp.MustCompile`。

## G2 · `sync.Mutex` 不可重入，锁内调 Load 会死锁

Python 用 `threading.RLock`，同一线程可重复取锁。Go 的 `sync.Mutex` 不行。
路由配置的 `Save` 里再调 `Load`（都取同一把锁）→ 测试挂起 30 秒后超时：

```
github.com/xzs/bridge_qoder/internal/route.(*Manager).Load
	.../route.go:131
github.com/xzs/bridge_qoder/internal/route.(*Manager).Save
	.../route.go:423
```

**修法**：`Save` 先 `Load`、再写文件，不跨调用持锁。

**检查清单**：任何 `Lock()` 之后又调自己包内的公开方法，都要确认该方法是否也取锁。

## G3 · Windows 时钟精度 15 ms，时钟派生的 UUID 会撞号

前缀会话缓存需要给每个新前缀生成一个上游 `session_id`。第一版用
`time.Now().UnixNano()` 填充字节：

```go
now := time.Now().UnixNano()
for i := range b { b[i] = byte(now >> (uint(i%8) * 8)) }
```

两个连续调用落在同一 tick → 同一个 UUID → **两个不同会话被映射到同一个上游 session**。
测试 `TestMemoryPrefixAffinity`（「两个账号不能共用 session」）抓出来的。

**修法**：改用 `crypto/rand.Read`；失败时退到 `sha256(时钟|原子计数器)`。

**教训**：任何「唯一 ID」都不要用时钟派生，尤其是 Windows。`hash/fnv` + 计数器也不够，
并发下仍需原子性。

## G4 · LRU 只淘汰「已过期」项 → 缓存无界增长

`TestMemoryCacheLRUBound` 写入 20 条（上限 4）后断言 entries ≤ 8，实际 20。

原因：淘汰循环里加了 `if e.expires.Before(now)` 才删，未过期项永远留着。

**修法**：超上界直接淘汰最旧项，不看是否过期。

## G5 · 错误归类顺序把「本地无账号」报成「上游瞬时故障」

最初 `friendlyUpstreamError` 只按上游特征匹配，于是：

```
{"error":{"code":503,"message":"上游瞬时故障 (HTTP 503)：网关已对同账号自动重试仍失败，
 请稍后重试。上游详情：upstream HTTP 503: no usable account for realm 'cn'..."}}
```

用户会去查网络和上游，而真正原因是账号池为空。

**修法**：在函数开头先认本地前缀（`no usable account` / `API Key / routing account scope` /
`routing configuration error` / `model is only available in realm`），给出指向看板账号页的文案。

**同类问题**：错误包装改变了 `err.Error()` 的前缀，导致匹配失效。所以后来加了
`upstreamDetail(err)` 直接从 `*upstream.StatusError` 取 `Detail`，不再依赖包装后的文本。

## G6 · panic 恢复写在 `defer` 里但没有中间件包裹

`routeRequest` 里的 `defer recover()` 只能兜住同一 goroutine。SSE 流内若在
`w.Write` 后 panic，客户端拿到的是断流而非错误帧。

**结论**：守卫链设计成纯函数（`Process(frames, allowed) ([]Frame, *ToolCallError)`），
把「可能失败」的判断前移到写字节之前，减少流中途出错的概率。

## Q1 · 网关对「解析不了的模型名」静默按 auto 透传

这是本项目最危险的行为，必须理解。

实测（`max_tokens` 正常、模型名随便写）：

| 发送的 model | HTTP | credits |
|---|---|---|
| `Qwen3.8-Flash`（真模型） | 200 | 0.0028 |
| `qoder:Qwen3.8-Flash`（加前缀，旧版网关不认） | 200 | **0** |
| `cn:Qwen3.8-Flash`（同样不认） | 200 | **0** |
| `totally-bogus-model-xyz` | 200 | **0** |

即：**未知名字返回 200，但没有真实费用记录**，上游按 `auto` 路由。

**后果**：你既拿不到想要的模型，也看不出异常；客户端一切正常。

**修法（两层）**：
1. 网关 `catalog.StripModelPrefix` 剥掉 `qoder:` / `qoder/` / `qoder-`（大小写不敏感）。
2. 验证手段固定为「看 `usage.credits` 是否非 0」，不要只看 HTTP 200。

**重要例外（2026-11-16 实测）**：`credits` 为 None 不一定就是静默 auto。
`Qwen4-Max-Preview`（`qmodel_latest`）确认路由成功——有真实的 `completion_tokens`、
模型日志显示真实生成——但**上游对它不回报 credits**（原始 `usage` 为 `null`）。
对照其他模型（Qwen3.8-Flash 0.008 / DeepSeek-V4-Pro 0.065）均有记账。

判定改为两条并存，满足其一即认定路由成功：
- `credits` 非 0（正常记账），或
- `completion_tokens > 0` 且 `/usage/perf` 里该模型有真实生成。

**单看 credits 会把这类模型误判成「没路由到」**。

## Q2 · 官方改过名的模型，首次请求会解析失败

`qmodel_latest` 的显示名从 `Qwen3.7-Max` 改成 `Qwen4-Max-Preview`，但本地快照仍是旧名。
显示名 → key 的映射只在拉取模型清单时注册，请求先到就解析不到 → 落进 Q1 的陷阱
（`credits=None`）。

**修法**：`server.resolveModelKey` 解析失败时刷新一次模型清单（5 分钟缓存）再重试。

**验证**：修前 `Qwen4-Max-Preview` 的 `credits=None`，修后 `0.017`。

## Q3 · `max_tokens` 太小会与思考预算冲突

批量探测模型时用 `max_tokens: 1` 配 `reasoning_effort: xhigh`，上游返回：

```
The thinking_budget parameter must be a positive integer and not greater than 262144
```

不是网关缺陷，是上游对「输出预算 vs 思考预算」的约束。

**用法**：批量探测给 `max_tokens >= 16`；正常使用不会遇到。

## Q4 · 408/418 是上游把 provider 故障包装成 4xx

`_is_transient_upstream` 里 418 与 5xx 同级对待，因为上游会把内部故障包成
`418 + provider_error`。按「4xx 是客户端错」处理会误判成不可重试。

**同时**：`401/403/429` 永远不走瞬时重试路径，它们各有专门的账号处理逻辑。

---

## Q5 · 请求体常量错误不能被 `"Range of "` 之外的变体漏掉

上游对超限输出回 `400 invalid_parameter_error: Range of max_tokens should be [1, 131072]`。
最初匹配带引号的 `"Range of `，JSON 里若不是这个形态就漏判。

**修法**：同时匹配 `Range of `（无引号）。这类错误换号也不会成功，必须走
`IsRequestFault` 直接抛给客户端，**不冷却账号**——否则轮换会把整池冷 60 秒，
其他用户跟着吃 503。

## Q6 · 本机凭证目录被两个进程共享时有过期刷新竞争

先用 8791 读 Python 版的 `accounts/` 做验证，日志显示两边都在回写账号文件
（06:53 两次 token 刷新落盘）。文件锁只在进程内有效。

**修法**：切到本仓库 `.gitignore` 覆盖的 `accounts/`，并停掉另一个实例。
**原则**：同一 `accounts/` 目录同一时刻只允许一个网关进程。

## C1 · Codex 不按 slug 前缀选 provider（核心结论）

用真实抓包确认（`codex exec` 打到本地捕获服务器，`wire_api="responses"`）：

| 配置的 `model` | 服务端收到的 `model` |
|---|---|
| `cn:Qwen3.8-Flash` | `cn:Qwen3.8-Flash` |
| `glm-5.3` | `glm-5.3` |
| `237/Qwen3.8-27B` | `237/Qwen3.8-27B` |

**前缀原样透传，Codex 不做任何剥离，也没有「前缀→provider」映射**。
模型目录条目的结构里根本没有 provider / namespace 字段。

**推论**：
- `qoder:` 前缀必须配合「指向本网关的 provider」使用。
- 站点的 `ss` provider 不服务这些模型：实测 `qoder:Qwen3.8-Flash` 与裸名
  `Qwen3.8-Flash` 均返回 `503 model_not_found`。

## C2 · 0.167 起 profile 必须独立成文件

在主 `config.toml` 里写 `[profiles.qoder]` 会直接报错：

```
Error loading config.toml: --profile `qoder` cannot be used while ... contains
legacy `profile = "qoder"` or `[profiles.qoder]` config; move those settings into
C:\Users\xzs\.codex\qoder.config.toml and remove the legacy profile selector/table.
```

**正确布局**：
- `config.toml` → `[model_providers.qoder]`（provider 本身）
- `qoder.config.toml` → `model_provider` / `model` / `model_reasoning_effort`

用法 `codex --profile qoder exec "..."`。

## C3 · 三个字段被 Codex 静默丢弃

用 `codex debug models` 对比「文件里写的」与「实际生效的」：

**被丢弃**：`max_output_tokens`、`supports_parallel_tool_calls`、`supports_reasoning_summaries`

**Codex 自己补上的**：`include_apps_usage_instructions`、
`include_plugin_usage_instructions`、`node_repl_auto_review_required`、
`node_repl_disabled`、`supports_experimental_context`、`supports_reasoning_effort_updates`

**结论**：写 `max_output_tokens` 无效，输出上限由上游决定。脚本已不再写这三项。

## C4 · 模型目录的必填字段比想象的多

删一个字段就**整个文件**解析失败（没有逐条容错）。必填：

`slug`、`display_name`、`supported_reasoning_levels`（可为 `[]`）、`shell_type`、
`visibility`、`supported_in_api`、`priority`、`support_verbosity`、
`truncation_policy`、`experimental_supported_tools`（可为 `[]`），
以及 `base_instructions` 或 `model_messages.instructions_template` **二者之一**。

`visibility` 枚举只有 `list | hide | none`，写 `hidden` 会被拒。

## C5 · `priority` 是升序，最低值成为默认项

`priority` 从小到大排列，最小的成为 `isDefault`。这与仓库里一份旧笔记
（写「降序」）矛盾——旧笔记已过时。

**实践**：新增模型的 `priority` 不要小于现有默认项，否则会抢走默认。

## R1 · 编译产物与运行时状态必须分开忽略

编译产物（`/qoder-proxy.exe`）和运行时状态（`accounts/` `usage/` `logs/`）性质不同：
前者可重新生成，后者含**凭据**。两者都要忽略，但理由不同。

**验证**：`git status --porcelain --ignored` 应能看到这些目录以 `!!` 开头。

---

## R2 · 凭据被复制进工作树的风险

曾计划把 Python 版的 `accounts/` 整体复制到 `runtime/`，被安全策略拦下——因为
`runtime/` 不在 `.gitignore` 里，一次 `git add -A` 就会把真实 token 提交进去。

**做法**：
1. 复制前先 `git check-ignore -v <目标路径>` 确认命中忽略规则。
2. 只复制需要的单个文件，不整目录复制。
3. 提交前固定执行 `git diff --cached --name-only | grep -E '^(accounts|usage|logs)/'`，
   有输出就说明要撤回。
