## 进程模型

- 单进程、`net/http` 每请求一 goroutine。
- 默认监听 `127.0.0.1:18090`。端口优先级：`--port` >`PORT` 环境变量 > 默认值。
  两者都校验 `1–65535`，越界立即启动失败并打印原因（历史事故见《踩坑笔记》G7）。
- SSE 用 chunked + keep-alive（不设 `Content-Length`），不手动加`Connection: close`
  —— 否则连接池型客户端会复用半关闭 socket，表现为「一直重连」。
- 后台常驻：模型预热、调度器（默认开，可通过 `code/accounts/scheduler/state.json` 关）、
  缓存保温（默认关）、日用量折叠（5 分钟）。
- 启动时探测端口：若已有 `qoder-proxy` 应答则打印「已在运行」并退出。

## 协议对齐（不可改动部分）

| 项 | 值 / 规则 |
|---|---|
| 请求体编码 | 标准 Base64 → 尾/中/首三段轮转 → 自定义字母表映射，`=` →`$` |
| 身份 JSON | 9 个键，键名排序 + 紧凑 + 非 ASCII 不转义 + `nil` →`""` |
| COSY Bearer | `md5(payload_b64 \n cosyKey \n date \n body \n path)`，path 去掉`/algo` |
| 会话密钥 | 16 ASCII 字符，同时作 AES-128 的 key 与 iv；RSA-1024 包裹 |
| 设备身份 | `md5(salt:uid)` → UUIDv4 形态（第 13 位`4`、第 17 位`a`） |
| cosy-version | `1.1.75`（`QD_COSY_VERSION` 可覆盖） |
| 主机候选 | CN: `gateway.qoder.com.cn`；INTL:`api3` →`api2` →`api1` |

`baseprompt.json` 与双区模型快照在`.gitattributes` 里标了`-text`，禁止任何换行
或尾随空格规范化——它们必须与官方逐字节一致。

## 安全边界（2026-11-17 第二轮加固）

上一轮收紧了「谁可以看到凭据」，这一轮补的是**凭据本身能被谁拿走**。四个缺陷
都是「读起来像防护、实际不生效」的类型，均已修复并加了回归测试。

| # | 缺陷 | 真实影响 | 修复 |
|---|---|---|---|
| S1 | 管理端点带 `Access-Control-Allow-Origin: *` | 操作者访问任意网页，该页即可跨域读取 `/accounts/export?secrets=1`，拿走全部账号 token | CORS 改为允许列表，只剩推理端点与公开探活 |
| S2 | `/panel/login` 无频率限制 | 默认口令 `admin`，局域网脚本可在秒级穷举，随后导出全部凭据 | 按客户端 IP 限速：5 次失败起 30s 冷却，逐次翻倍，上限 15 分钟 |
| S3 | 日志不脱敏 | 上游错误/URL 会带 token 落盘，`/logs` 与 `/logs/export` 对任何面板会话可读 | `logx.Redact` 在唯一出口处脱敏，导出时再洗一次（兼容旧日志） |
| S4 | Windows 上 `0o600` 被忽略 | 账号文件继承 `BUILTIN\Users:(RX)`，同机其他账号可读 token、可改文件 | 用`icacls ` 显式收紧 ACL；目录与文件都处理 |

### S1：CORS 不能开在管理面

面板用 `X-Panel-Token` 头鉴权，不是 Cookie。这决定了 CORS 通配符的后果比通常更重：
浏览器的 SameSite 保护对「头部鉴权」不起作用，任何页面都能发出带自定义头的请求。

```
// 旧：前缀匹配，把管理面一起放开了
prefixes := []string{"/v1/", ..., "/accounts", "/settings", "/logs", "/agents", ...}
```

现在只允许推理与公开探活；新增管理路由不会自动获得 CORS。

### S2：默认口令必须配合限速

`sessionTTL` 是 7 天，面板 token 是自校验签名。一旦猜中口令，攻击者可以长期持有会话，
而默认口令是公开文档里的 `admin`。限速按 `RemoteAddr`（不信任 `X-Forwarded-For`，
否则轮换该头即可绕过）；成功登录会清空计数。

### S3：脱敏放在日志的唯一出口

`logx.Logger.Log` 是文件、stderr、内存环三个 sink 的唯一入口，所以在那里调用 `Redact`，
新加的日志行就不可能绕过。`/logs/export` 会再洗一次磁盘文件，因为修复前写下的日志可能已含 token。

识别的形态：`Bearer ...`、`dt-/drt-/pt-/jrt-`、`cosy-key`、JSON 里的`"accessToken"`、
`?token=`/`api_key=` 查询串、`panel_session_secret`。脱敏保留字段名与原值前 4 位，便于区分事件。

### S4：Windows 的 0o600 是「建议值」

Go 的 `os.WriteFile(path, data, 0o600)` 在 Windows 上不设置 ACL，文件继承父目录的 ACE。实测：

```
> icacls code\accounts\01a1df2a-....json
... BUILTIN\Users:(I)(RX)              <- 其他本地账号可读
    NT AUTHORITY\Authenticated Users:(I)(M)   <- 任何已认证进程可改
```

修法是 `icacls` 显式重建 ACL（本项目零依赖，故不用 `golang.org/x/sys/windows`）。
两个细节踩过：

1. **`/inheritance:r` 只删继承的 ACE，保留显式的**。父目录若曾有显式 `BUILTIN\Users:(R)`，
   加固后依然可读。必须额外 `/remove:g` 掉 Everyone / Authenticated Users / BUILTIN\Users。
2. **目录也要收紧**。只改文件时，父目录的继承规则会给之后新建的账号文件重新授权。

验证（真实目录实测）：

```
> icacls code\accounts
accounts BUILTIN\Administrators:(OI)(CI)(F)
         NT AUTHORITY\SYSTEM:(OI)(CI)(F)
         DESKTOP-XXX\xzs:(OI)(CI)(F)
```

## 签到数据流（2026-11-17）

签到有两条路径，**活动平台优先**、旧 sash 兜底。顺序不可交换：官方已停用旧接口，
先调旧接口只会得到 404 并把整个功能卡死。

```
tasks.RunBatchCheckin                 tasks/tasks.go
  └ acc.Checkin                      accounts/checkin.go
     ├ CampaignCheckin(gap, onlyCredits)      ← 主路径
     │  ├ FetchCampaigns()                    GET  /sash/api/v1/me/campaigns
     │  │   └ campaignListNeedsRetry()        空列表重试 0.8s / 2.0s
     │  ├ 分类（先 CLAIMED，后 actionType）
     │  ├ ClaimCampaign(id)                   POST /campaigns/{id}/claim
     │  ├ IsCampaignBlocked()                 同人去重 6 小时冷却
     │  ├ StampCheckin()                      只写一次本地日期
     │  └ NextCheckinWindow()                 下次 10:00（UTC+8）
     └ legacyCheckin                     ← 仅在活动列表取不到时
        ├ CheckinStatusFor()                  GET  /sash/api/v1/me/daily-check-in/status
        └ POST /sash/api/v1/me/daily-check-in/claim
```

为什么「分类先于 actionType 过滤」：官方在领取成功后会把这个活动的 actionType 从
`CLAIM_BENEFIT` 降级为 `VIEW_DETAILS`。若先按 actionType 过滤，
「今天已经领过」会被误判成「不可领取的详情类活动」。

兜底判据是「活动平台有没有给出结论」，不是「活动平台成功与否」：
已领、被同人去重、名额发完、成就未完成、明确无可领活动，都算结论，不再兜底。
