### `.gitignore` 新增规则

原本只覆盖编译产物与运行时状态，缺「中间产物/调试残留」一类。补齐：

```
# Build / debug intermediates
*.tmp
*.tmp.*
*.orig
*.rej
*.bak
*.bak-*
!docs/**/*.md
__pycache__/
*.py[cod]
*.swp
*.swo
*~
```

说明：

- `*.tmp` / `*.tmp.*`：代码里多处写临时文件（`settings.json.tmp`、
  `usage-summary.json.<pid>.<tid>.tmp`、`agents` 的 `.qoder-proxy.tmp`）。
- `*.bak-*`：`tools/add_qoder_models.py` 每次写入都会生成
  `bridge_models.json.bak-<时间戳>`（在 `~/.codex/`，但仓库内也可能产生同类备份）。
- `__pycache__/` / `*.py[cod]`：`tools/*.py` 运行后的字节码。
- `*.swp` / `*~`：编辑器残留（含任务栏关闭产生的 `qoder-proxy.exe~`，已有单独规则）。

### 校验

```bash
git status --porcelain --ignored | grep '^!!'    # 应能看到 accounts/ usage/ logs/ 与产物
git check-ignore -v foo.tmp                      # 确认新规则命中
```

### 1. 起因

需求：把 `http://127.0.0.1:8790/` 支持的模型加进 Codex 的 `bridge_models.json`。

### 2. 遇到的两个静默失败

**（a）前缀不被识别 → 静默按 auto 计费**

直接发 `qoder:Qwen3.8-Flash` 得到 200，看起来正常。对照测试才发现：
发一个完全胡编的 `totally-bogus-model-xyz` 也返回 200，两者 `credits=0`，
而真模型是 `0.0028`。

```
model=qoder:Qwen3.8-Flash      credit=0
model=totally-bogus-model-xyz  credit=0
model=Qwen3.8-Flash            credit=0.0028
```

即：**未知模型名被原样透传给上游，上游按 auto 路由**。

**（b）改名模型解析不到**

`Qwen4-Max-Preview` 是官方把 `Qwen3.7-Max` 改名而来，本地快照还是旧名。
显示名映射只在拉取模型清单时注册，请求先到就解析失败 → 又落进（a）。

### 3. 修复与验证

| 修复 | 验证 |
|---|---|
| 网关剥离 `qoder:` / `qoder/` / `qoder-` | 同请求 `credits` 从 `0` → `0.0028` |
| 解析失败时刷新模型清单 | `Qwen4-Max-Preview` `credits` 从 `None` → `0.017` |
| 加 `[model_providers.qoder]` + profile | `codex --profile qoder exec` 输出正确，网关 `credits=0.0167` |

### 过程中修掉的缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| RE2 不支持前瞻 | 启动即 panic | 前瞻改写为捕获分隔符 |
| `sync.Mutex` 不可重入 | 保存路由配置死锁 | `Save` 不跨调用持锁 |
| 时钟派生 UUID 撞号 | 两会话共用一个上游 session | 改用 `crypto/rand` |
| LRU 只淘汰过期项 | 缓存无界增长 | 超上界直接淘汰最旧项 |
| 错误归类顺序 | 本地「无账号」被报成上游故障 | 先认本地前缀 |
