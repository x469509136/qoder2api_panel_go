### 1. 拆包：边界设计对，落地只完成一半

边界是干净的：`qoder` 包不引用 `accounts`，不碰账号池/冷却/面板/持久化，出入参都是
值类型；`accounts` 侧用别名 + 转发函数保持历史 API 不变。

但**旧实现没有从 `accounts` 删掉**，两份同名符号并存，于是编译失败：

```

#   internal/accounts 报 69 个错误：
#     59 个 "X redeclared in this block"
#        realm.go 34、bridge.go 9、checkin.go 6、quota.go 3、token.go 3、
#        login.go 2、scan.go 2
#     10 个类型/语义错误：
#       bridge.go:93  NormalizeQuotaPayload 返回值不匹配（[]qoder.Composition vs []Composition）
#       bridge.go:97  LedgerIsUnknown 实参 *Credits 不是 *qoder.Credits
#       bridge.go:100 NextCheckinWindow 返回值不匹配
#       bridge.go:103 ExpiryOf 实参类型不匹配
#       bridge.go:106 ParseVPCEndpoint 返回未导出的 *qoder.vpcEndpoints
#       checkin.go:645 为外部类型 Campaign 定义方法（Go 不允许）

反过来新包自己是好的：

```

token、login、scan 六处里被搬走的实现还留着。要么删旧实现，要么删 `bridge.go` 的
重复别名——现在两者并存。另外 `gofmt -l` 报 `accounts/bridge.go` 未格式化。

### 2. `build-win10.bat`：流程能用，但四处与约定冲突

流程本身是对的：找 `go.exe`（`GO_BIN` → 默认安装路径 → `PATH`）→ `CGO_ENABLED=0` →
`go mod download` → `go vet ./...` → `go build -trimpath -buildvcs=false` → 拷
`web/ i18n/ assets/` → 建空 `accounts/ usage/ logs/` → `certutil` 出 SHA256。
版本号用 `git rev-parse --short HEAD` 注入 `internal/server.Version`。`go` 会把控制台
代码页改成 UTF-8，脚本在每次调用后都补了 `chcp 936 >nul`。

| # | 现状 | 要求 | 后果 |
|---|---|---|---|
| 1 | UTF-8（无 BOM） | GB2312 无 BOM | 含 217 个非 ASCII 字符；`chcp 936` 下中文 echo 乱码 |
| 2 | 209 行全 LF | CRLF | `.gitattributes` 的 `*.bat eol=crlf` 只改行尾，**编码仍是 UTF-8**，问题 1 不会自愈 |
| 3 | 默认 `OUT_DIR=<repo>\dist-win` | 产物应被忽略 | 原 `.gitignore` 无此规则，`git check-ignore` 返回 1 |
| 4 | 引用 `stop-win10.bat` / `start-win10.bat` | 同目录应存在 | 两者都不存在：`clean` 会先报 call 失败再继续删，提示的启动方式也是空指引 |

### 1. 主路径：活动平台

```
GET  /sash/api/v1/me/campaigns        -> 列表（含 claim_status / benefit / actionType）
POST /sash/api/v1/me/campaigns/{id}/claim -> 领取（幂等，重复返回 CLAIMED+replayed）
```

流程：拉列表（强制不吃缓存）→ 空结果重试（0.8s / 2.0s）→ 逐条分类 → 对可领的发
claim（间隔 gap）→ 汇总。

### 2. 分类规则（顺序不能换）

| 上游状态 | 归类 | 是否算失败 |
|---|---|---|
| ` CLAIMED ` 且 benefit.amount > 0 | 已领取 | 否 |
| ` CLAIMABLE ` + actionType 可领 | 发起 claim | — |
| ` CLAIMED ` 但无奖励金额 | 详情类，忽略 | 否 |
| ` unavailableReason = REDEMPTION_CODE_OUT_OF_STOCK` | 名额发完（pending） | 否 |
| ` unavailableReason = ACHIEVEMENT_NOT_COMPLETED` | 成就未完成（locked） | 否 |
| claim 返回同人去重 | blocked | 否 |
| claim 其它错误 | errors | **是** |

### 3. 兜底边界

只有「活动列表取不到」才调旧接口。判据是「有没有结论」而不是「OK 不 OK」：
已领、被同人去重、名额发完、成就未完成、明确无可领活动，都算结论。

### 4. 批量结果语义修正

改前：`RunBatchCheckin` 只有「已签到 / 成功 / 失败」三类，
「同人去重」和「名额发完」都落进成功，` credit_added ` 为 0，
从汇总上看不出发生了什么。

改后新增两列：

| 字段 | 含义 |
|---|---|
| `already` | 今日已领取的账号数 |
| `blocked` | 被上游按人去重的账号数 |

两者都不计入 `failed`，也不计入 `credit_added`——这是本次特意区分的语义。

### 1. S1：CORS 通配符暴露管理面

审计方法：列出所有挂 CORS 头的路径，与 `dispatchManagement` 的管理面逐一比对。

旧的 `corsAllowed` 是前缀匹配，`/accounts`、`/settings`、`/logs`、`/agents`、
`/admin`、`/usage`、`/tasks`、`/diag`、`/credits`、`/panel` 全部命中，
回 `Access-Control-Allow-Origin: *`。

为什么这是凭据泄露而不只是「信息暴露」：

- 面板用请求头鉴权，而浏览器对头部鉴权没有 Cookie 的 SameSite 保护；
- 同一份响应里有 `/accounts/export?secrets=1`，即明文 token；
- 因此「管理面允许跨域」等于「浏览器不再是边界」。

修复：允许列表只保留推理端点（9 条）与公开探活（`/ping`、`/healthz`、`/livez`、
`/readyz`、`/health`）。新增管理路由不会自动获得 CORS。

### 2. S2：面板登录无频率限制

默认口令 `admin` + TTL 7 天 + 自校验签名 token = 一旦猜中就长期有效。

修复：`loginThrottle`，键为 `RemoteAddr`。前 5 次失败不惩罚（容忍手抖），第 6 次起
30s 冷却并逐次翻倍、上限 15 分钟。成功登录清空计数。

两个刻意的选择：

| 选择 | 理由 |
|---|---|
| 不读 `X-Forwarded-For` | 信任它等于允许轮换该头绕过限速；反代应在边缘自己限速 |
| 锁定期间正确口令也 429 | 否则 200/429 的差异本身就是口令正确性旁路 |

### 3. S3：日志与错误信息不脱敏

审计了所有 `s.log.*` 调用点，会带外部字符串的有：`model discovery failed on <url>: <err>`、
`upstream status %d: %s`、`error: model=%s status=%d account=%s: %s`、`usage persist failed`。
这些字符串可能含 `Bearer`、查询串 token 或整段账号 JSON。

修复位置选择：放在 `logx.Logger.Log` 而不是调用点。原因：文件、stderr、内存环三个 sink
都从这一个函数出去，从入口做才能保证新加的日志行无法绕过。

`/logs/export` 会再洗一次磁盘文件——修复前写下的日志可能已含 token，这是必须的兜底。

脱敏范围（保留字段名 + 原值前 4 位，便于区分事件）：

| 形态 | 例子 |
|---|---|
| Bearer | `Authorization: Bearer dt-...` |
| Qoder token 族 | `dt- / drt- / pt- / jrt-` |
| COSY 头 | `cosy-key` / `cosy-user` / `cosy-machineid` |
| JSON 字段 | 键名为 accessToken / refreshToken 的片段 |
| 查询串 | `?token=` / `api_key=` |
| 配置字段 | `panel_session_secret` / `panel_password_hash` |

### 4. S4：Windows 上 0o600 不生效

实测证据（本机仓库，未修改前）：

```
> icacls code\accounts\01a1df2a-...json
BUILTIN\Users:(I)(RX)                    <- 其他本地账号可读
NT AUTHORITY\Authenticated Users:(I)(M)  <- 任何已认证进程可改
```

修复：`icacls` 显式重建 ACL（零依赖，不用 `golang.org/x/sys/windows`）。

过程中修掉了自己引入的一个缺陷：第一版只用 `/inheritance:r`，而它只删继承的 ACE、
保留显式的。测试因此失败（`Users:(OI)(CI)(R)` 仍在），补上
`/remove:g` Everyone / Authenticated Users / BUILTIN\Users 才通过。

另外把目录也纳入加固：只改文件时，父目录的继承规则会给之后新建的账号文件重新授权。

实测结果（真实目录，启动一次后）：

```
> icacls code\accounts
accounts BUILTIN\Administrators:(OI)(CI)(F)
         NT AUTHORITY\SYSTEM:(OI)(CI)(F)
         DESKTOP-XXX\xzs:(OI)(CI)(F)
```

账号文件与 `settings.json` 同样只剩这三条。

### 2. `.gitattributes`：统一 LF，快照逐字节冻结

新增文件，规则按「从宽到窄」排列（gitattributes 是**最后匹配者生效**）：

```
* text=auto eol=lf          # 通用
*.go/*.json/*.md/... eol=lf # 具体类型
*.bat/*.cmd/*.ps1 eol=crlf  # Windows 脚本例外
code/assets/*.json -text    # 协议对齐文件例外（放最后，覆盖上面的 json 规则）
```

三条要点：

- 本机全局 `core.autocrlf=true`。没有 `eol=lf` 兜底时，Windows 检出会把所有
  文本变成 CRLF，`git diff` 出现大量「内容无变化的改动」。
- `*.bat` / `*.cmd` / `*.ps1` 必须 CRLF，否则 cmd.exe 的 `goto`/`label` 与括注块
  会误判（与 AGENTS.md 的 bat 编码规范一致）。
- `baseprompt.json` 与双区快照标 `-text`：它们与官方客户端逐字节对齐，行尾或
  尾随空格变化会降低上游 prompt 前缀缓存命中率。

> 第一版把 `-text` 写在 `*.json` 之前，被后置规则覆盖，`git check-attr` 显示
> `text: set`。已调整顺序并逐条验证，详见《踩坑笔记》R6 / R7。

| 3 | `GET /health` 在「未配置 Key」时对任何来源返回 `uid` | `--host 0.0.0.0` + 无 Key 时，局域网任何人可读到当前账号 uid/域/到期 | 仅面板会话 / 有效 Key / 回环地址可见，其余返回匿名快照 |
| 4 | 两处 `gofmt` 不合规 | 若 CI 加 `gofmt -l` 会失败 | `gofmt -w` |

第 2、3 条是行为变更，**会影响脚本**：手写 `curl /accounts/export` 拿到的 JSON
不再含 token，需要明文时必须显式加 `?secrets=1`。

### 2. 遇到的两个静默失败

**（a）前缀不被识别 → 静默按 auto 计费**

直接发 `qoder:Qwen3.8-Flash` 得到 200，看起来正常。对照测试才发现：
发一个完全胡编的 `totally-bogus-model-xyz` 也返回 200，两者 `credits=0`，

```
model=qoder:Qwen3.8-Flash      credit=0
model=totally-bogus-model-xyz  credit=0
model=Qwen3.8-Flash            credit=0.0028
```

即：**未知模型名被原样透传给上游，上游按 auto 路由**。

`Qwen4-Max-Preview` 是官方把 `Qwen3.7-Max` 改名而来，本地快照还是旧名。
显示名映射只在拉取模型清单时注册，请求先到就解析失败 → 又落进（a）。
