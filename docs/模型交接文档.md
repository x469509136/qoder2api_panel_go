## 2. 选型建议

| 场景 | 推荐 |
|---|---|
| 日常编码、想省钱 | `qoder:Qwen3.8-Flash`（免费） |
| 需要 1M 上下文 | `qoder:Qwen4-Max-Preview` / `qoder:GLM-5.3-Flash` / `qoder:Step-5-Preview` |
| 深度推理、质量优先 | `qoder:Kimi-K3.1-Pro`、`qoder:DeepSeek-V4-Pro`（档位偏高端） |
| 不确定选哪个 | `qoder:Auto`（由上游按负载分配） |
| 多模态输入 | 除 `Fast` 外均支持图像（`Fast` 的 `is_vl` 未单独核验） |

## 3. Codex 接入布局

Codex 的模型目录只是**元数据/选择器层**，不参与路由：slug 原样作为 `model`
发给当前 `model_provider` 的 `base_url`。因此必须同时配 provider。

### 3.1 `C:/Users/xzs/.codex/config.toml`

```toml
[model_providers.qoder]
name = "qoder"
wire_api = "responses"
requires_openai_auth = false
base_url = "http://127.0.0.1:18090/v1"
# 网关配置了 API Key 时取消注释，并把 Key 放进环境变量
#env_key = "QODER_PROXY_API_KEY"
```

默认 `model_provider = "ss"`（station）**保持不变**，切换靠 profile。

### 3.2 `C:/Users/xzs/.codex/qoder.config.toml`

0.167 起 profile 必须独立成文件（主配置里写 `[profiles.*]` 会报错）。

```toml
model_provider = "qoder"
model = "qoder:Qwen3.8-Flash"
model_reasoning_effort = "low"
```

### 3.3 用法

```bash
codex --profile qoder exec "你的任务"
```

启动横幅应显示 `provider: qoder` 与 `model: qoder:<名字>`。

## 5. 验证模型是否真的在工作

唯一可靠标准：**网关侧 `usage.credits` 非 0**。

```bash
curl -s -X POST http://127.0.0.1:18090/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qoder:<名字>","max_tokens":16,
       "messages":[{"role":"user","content":"hi"}]}' | python -c "
import sys,json;d=json.load(sys.stdin)
print('credits =', (d.get('usage') or {}).get('credits'))
"
```

`credits` 为 0 或缺失 → 名字没解析到，上游按 `auto` 处理（仍然返回 200）。

## 6. 已知限制

| 项 | 说明 |
|---|---|
| `max_output_tokens` 不生效 | Codex 0.167 静默丢弃该字段（`codex debug models` 里看不到）。实际输出上限由上游决定。 |
| `qoder:` 前缀只对本网关有效 | station（`ss`）不认这个前缀，返回 `503 model_not_found`。 |
| 改名窗口 | 官方改名后本地快照会滞后。网关在解析失败时会刷新模型清单兜底，首次请求可能多一次拉取（约 1 秒）。 |
| 跨区模型 | 本次只导出 `cn` 区 13 个。INTL 区模型不同（含 `ultimate`/`performance` 等独占项），需要时用 `?realm=intl` 或 `?merge_realms=1` 取。 |
| 未导入媒体类模型 | 官方清单里若有纯图像/视频模型，`codex` 侧用不到，未导入。 |

## 8. 签到与权益中心（2026-11-17 起）

签到的鉴权、额度与模型清单共用同一套账号凭证，但**走的是不同的上游接口**。
排查模型问题时不需要碰它；反过来，签到失败也不代表模型不可用。

| 步骤 | 接口 | 说明 |
|---|---|---|
| 列活动 | `GET /sash/api/v1/me/campaigns` | 官方现行入口，带桌面端请求头 |
| 领取 | `POST /sash/api/v1/me/campaigns/{id}/claim` | 幂等；重复领取返回 replayed |
| 旧接口（兜底） | `/sash/api/v1/me/daily-check-in/{status,claim}` | 官方已停用，仅在活动列表取不到时使用 |

**验证签到是否真的生效**（不要只看 HTTP 200）：调用后看返回体里的 `campaign` 字段，
`claimed` 非空才是本轮真实新增。`already` 表示今天早些时候已领；`blocked` 表示
同一设备下别的账号已领（上游按人去重，换号无效）。
